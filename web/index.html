01 / LA DÉMARCHE

De la source au graphique.

Chaque étape répond à un problème concret : identifier la bonne commune, éviter un prix mal attribué, distinguer une donnée absente d’un zéro et conserver les informations nécessaires pour comprendre le résultat.

  1. 1

    Collecter

    Des scripts Python ont été développés pour télécharger les fichiers DVF et interroger les API Overpass, OpenAQ, Géorisques et IGN. Un déclenchement automatique (cron) dans GitHub Actions lance ces scripts chaque jour pour actualiser les données dans Supabase, sans intervention manuelle. Chaque collecte conserve sa source et sa date pour pouvoir retrouver l’origine des chiffres.

  2. 2

    Préparer

    Avec Python et pandas, les codes INSEE sont harmonisés sur cinq caractères et les arrondissements de Paris, Lyon et Marseille regroupés par ville. Les prix et les surfaces sont convertis en nombres ; les ventes avec des valeurs manquantes, non numériques, nulles ou négatives sont écartées.

  3. 3

    Contrôler

    Des tests vérifient les règles de calcul, les unités et le périmètre communal. Pour chaque chiffre affiché, le site vérifie que la source et la date indiquées concernent bien les données utilisées. En cas de mise à jour incomplète, une alerte apparaît dans GitHub Actions avec le détail des problèmes.

  4. 4

    Restituer

    Les résultats sont stockés dans Supabase avec leurs métadonnées. La carte et les graphiques ont été développés en JavaScript pour partager les mêmes filtres et rendre les calculs consultables. Firebase héberge le site.

02 / LES DONNÉES

Une source pour chaque question.

Les données proviennent de fichiers publics ou d’API, des services interrogés automatiquement par les scripts. Les sources fournissent les observations ; le projet définit les filtres, les regroupements et les calculs utilisés pour construire les indicateurs ci-dessous.

Pourquoi les données INSEE ne figurent-elles pas dans les graphiques ?

Les essais sur les données INSEE ne sont pas encore intégrés à cette version. La population, les revenus et le chômage ne sont donc pas affichés. Le comparateur officiel de territoires ↗ permet de compléter la lecture.

03 / LES CHOIX D’ANALYSE

Nettoyer les données, c’est aussi prendre des décisions.

IMMOBILIER

Éviter les prix mal calculés

Une vente peut apparaître sur plusieurs lignes ou concerner plusieurs biens. Le calcul retient les ventes décrites sur une seule ligne pour limiter les erreurs d’attribution du prix.

SERVICES

Comparer toute la commune

Un cercle autour du centre ne couvre pas tous les quartiers. Le comptage utilise les limites de la commune pour inclure les services référencés dans l’ensemble de la ville.

QUALITÉ DES DONNÉES

Distinguer zéro et inconnu

Si une API ne répond pas, cela ne signifie pas qu’il n’y a aucun service ou aucun risque. La valeur est signalée comme indisponible et aucun chiffre n’est inventé.

COMPARAISON

Garder des indicateurs séparés

Un prix, un relevé d’air et une liste de risques ne décrivent pas la même chose. Les graphiques permettent de les croiser sans fabriquer une note de « meilleure ville ».

Comment les prix immobiliers sont-ils calculés ?

Un prix médian est un repère : la moitié des ventes analysées a un prix au m² inférieur, l’autre moitié un prix supérieur. Le calcul est fait séparément pour les maisons et les appartements, dans chaque ville.

Seules les ventes de maisons ou d’appartements décrites sur une seule ligne sont conservées. Le prix et la surface doivent être renseignés et positifs. Les prix inférieurs à 200 ou supérieurs à 20 000 €/m² sont écartés pour limiter les valeurs extrêmes. Il faut au moins 10 ventes analysées pour afficher un prix médian.

Ces filtres excluent une partie des ventes, y compris des transactions réelles. Le résultat donne un repère sur les ventes analysées, pas une estimation de tous les logements de la ville. La période et le nombre de ventes restent accessibles dans les fiches et les graphiques.

Comment les contrôles peuvent-ils être vérifiés ?

Les scripts conservent la source, la date de collecte, la commune et les informations utiles au calcul. Un rapport permet de retrouver les filtres immobiliers, les stations de mesure et les réponses des API. Des tests vérifient notamment les ventes sur plusieurs lignes, les unités de l’air et les limites communales.

Une vérification technique ne garantit pas que toutes les données sont complètes. Par exemple, un service absent d’OpenStreetMap peut exister dans la réalité.

05 / AIR

Que mesurent les stations proches ?

PM2.5 · µg/m³

Les PM2.5 sont des particules fines présentes dans l’air. Chaque point montre une mesure conservée pour une station proche de la ville.

Les mesures n’ont pas toutes été prises au même moment. Survolez un point pour connaître la station, sa distance et la date.

06 / RISQUES RECENSÉS

Quels types de risques sont documentés ?

Un point indique qu’un risque est mentionné pour la commune. Il ne dit pas si votre logement est exposé, ni à quel niveau.

Un risque absent de cette liste peut tout de même exister. Pour un bien précis, consultez Géorisques à son adresse.
